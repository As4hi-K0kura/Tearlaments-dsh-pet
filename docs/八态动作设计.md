# 人鱼少女桌宠 · 八态循环动作设计（v3）

**形态**：动画型桌宠，允许大动作。
**硬性要求**：每个状态是一条可无缝循环的动作脚本。
**v3 变更**：收紧元素白名单——**只允许该人鱼少女本人 + 她的水晶剑 + 法阵**。不再引入任何座椅、坐具、抱枕、怀表、沙漏、水泡、气泡、随行生物、服饰配件。

---

## 1. 元素白名单与判定标准

### 1.1 白名单

| 允许 | 说明 |
|---|---|
| **人鱼少女本人** | 身体、头、发、鳍耳、羽翼、**双腿（人形、无鱼尾）**、头冠、眼睛、表情、衣着的固有形态 |
| **她的水晶剑** | 角色原有道具，可用可脱手可出画（出画必须飞回） |
| **法阵** | 唯一允许引入的新增元素。由她自身产生、随她动作出现又消失 |
| **角色自身形变** | 她的身体自身散开/凝实、发光/黯淡——不是"引入的对象"，是她本人的状态变化 |

### 1.2 判定标准（以后新增动作时按此把关）

一个元素能不能用，只问两句话：

1. **它是不是独立于她存在、能被她"坐上去"或"拿在手里"？**
   是 → **禁用**。贝壳座椅、海螺枕头、怀表、水泡都属于这一类。
2. **它是不是从她身上随动作生灭、不具备独立存在性？**
   是 → **可用**。法阵属于这一类——她抬手它生，她收手它灭。

**灰区一律从严**：星芒、水花、花瓣、呼噜泡这类"一次性效果"也一并去掉。庆祝不靠水花，靠身体动作本身。

### 1.3 去掉元素后，各态的辨识度靠什么

| 状态 | 取代道具的辨识手段 |
|---|---|
| 待机 | 站立悬浮 + 伸懒腰舒张 + 环顾四周 |
| 思考 | 盘腿悬浮 + 托腮 + 视线离屏 + 手指敲节拍 |
| 调用工具 | **法阵** + 双手刺剑 + 身体前倾 |
| 等待 | 抱膝蜷缩 + 瞌睡点头 + 打哈欠 |
| 完成 | 跃起 + 空中转体 + 星星眼 |
| 出错 | **法阵失控炸散** + 剑脱手 + 自我重建 |
| 拖拽 | 悬空 + 头发全部向上飘 |
| 休眠 | 侧躺 + 抱剑入眠 + 闭眼 |

## 2. 循环闭合三型

| 型 | 名称 | 接缝处发生什么 | 适用 |
|---|---|---|---|
| **静默闭合** | silent | 什么也不发生，末帧直接接首帧 | 待机、思考、等待、完成、拖拽、休眠 |
| **事件闭合** | event | 接缝被设计成叙事事件：法阵炸散、自我重建 | 出错 |
| **冲程闭合** | reciprocal | 接缝落在往复动作的反向前摇，像弹簧储能 | 调用工具 |

出错态的事件接缝完全由**法阵**完成——法阵失控炸散 → 她慌乱 → 沮丧 → 她重新召出小法阵把自己聚拢 → 叉腰挺胸复位。既是叙事高潮，又不越元素白名单。

---

## 3. 仍然生效的物理规则

1. **惯性滞后** — 发丝、裙摆、鳍耳比身体晚 0.15–0.30s。
2. **速度归零** — 静默闭合与冲程闭合的接缝点必须落在速度最小处。
3. **相位连续** — 呼吸、翅膀相位在接缝处对齐。
4. **出画入画配对** — 飞出画面的剑必须在本循环内回来。

## 4. 八态动作脚本

### ① 待机 `idle` — 静默闭合 / 4.0s / 120 帧

**初始姿态**：悬浮站立，双腿自然下垂并拢；**左手（画面右侧）垂握水晶剑**（剑尖朝右下）；右臂（画面左侧）放松微张；肩背放松，浅笑。

| 时间 | 动作 |
|---|---|
| 0.00–0.70 | 蓄力：身体微微下沉，肩膀耸起（吸气），翅膀收紧 |
| 0.70–1.90 | 舒展：身体升至 +12%，翅膀完全展开一次（60°），左臂上抬举过头顶**伸了个懒腰**；发丝裙摆滞后 0.20s 跟上 |
| 1.90–3.10 | 环顾：身体缓缓向左转 20°，头跟着转、视线扫过四周；剑随身体画出弧线 |
| 3.10–3.60 | 回头：头先转回正面，身体后到（跟随延迟 0.1s） |
| 3.60–4.00 | 定格：眨眼一次，裙摆轻甩一次，鳍耳轻抖，呼出一口气（胸腔回落） |

**接缝**：静默。4.00s 高度、朝向、翅膀开合角、眨眼与裙摆甩动节奏全部回到 0.00s。
**辨识锚**：站立悬浮 + 伸懒腰 + 环顾。身体的"舒展感"就是待机的表情。

---

### ② 思考 `thinking` — 静默闭合 / 5.0s / 150 帧

**初始姿态**：悬浮盘腿（在空中盘腿而坐），身体前倾，双手托腮，**睁眼且视线朝左上**（循环起止帧取睁眼态，静帧也能读出"思考"），双腿盘在身前。**水晶剑插在她身旁右侧的地上**（剑柄带宝石在右上、剑尖朝左下），她**双手都在腮上、根本没有握剑**。

> **第 9 轮改写（原版是 5 拍，见下方"原设计"）**。改写原因：① v2 提示词写"左手握剑"与参考帧直接打架 → 动作做不出来；② 5 个拍点超出模型在 5 秒内的承载（≤3 拍）。**实际交付版（v18）**：

| 时间 | 动作 |
|---|---|
| 0.00–1.60 | 点颊：睁眼，**食指指尖轻点自己颧骨 1 下**（掌心始终压在脸颊上、不离开脸），视线向左上 |
| 1.60–3.30 | 闭眼：视线保持左上，眼睛缓缓闭上，头微微往下压一点点 |
| 3.30–5.00 | 回：眼睛重新睁开、视线回到左上、头抬回 Picture 1 的角度，回到起点 |

**接缝**：静默。5.00s 回到盘腿坐姿，双手托腮，视线左上，身旁剑姿态不变。
**辨识锚**：盘腿 + 托腮 + **视线离开用户**。这是"处理中"与"发呆"的分界。

**原设计（v2，5 拍，已废弃）**：点颊 → 手指在膝上敲节拍 → 换思路（闭眼转头向右、换手托腮、身体转 15°）→ 顿悟（身体后仰、手掌拍大腿、裙摆弹起）→ 收（回起点）。

---

### ③ 调用工具 `calling_tool` — 冲程闭合 / 2.8s / 84 帧

**初始姿态**：站立悬浮，**左手（画面右侧）持剑垂于身侧**，右臂（画面左侧）前伸；**身前浮现一枚缓慢自转的法阵**（白名单元素）。

| 时间 | 动作 |
|---|---|
| 0.00–0.60 | 法阵加速：字符浮现、自转加速，她后仰蓄力，剑抬起至肩前 |
| 0.60–1.20 | 刺出：左手持剑、右臂并上，双手前刺，剑尖对准法阵中心，身体前倾 15° |
| 1.20–1.90 | 灌入：法阵骤然亮起并向前扩张一圈冲击环（法阵自身的效果），她握剑的手臂泛起光纹 |
| 1.90–2.40 | 收：法阵缩回一点，剑拉回身侧，身体回正 |
| 2.40–2.80 | 回初始：法阵恢复慢速自转，剑垂下，姿态与转速回到 0.00s |

**接缝**：冲程。2.80s 位于蓄力前的最低点（剑已归位、速度为零），自然接上下一轮。
**辨识锚**：法阵 + 刺剑 + 前倾。**法阵是本态的存在证明**，也是与思考唯一可靠的区分。

---

### ④ 等待 `waiting` — 静默闭合 / 6.0s / 180 帧

**初始姿态**：悬浮抱膝，蜷成一团，**右臂（画面左侧）搭在膝上、手背搁住膝盖**，**左手（画面右侧）垂下握剑、剑尖朝右下**；双腿曲起环抱自己，眼睛半闭。

> 修正记录：原设计为"双手环抱膝盖 + 剑横放在腿上"。实拍发现抱膝姿态下模型容易**多补一只前臂和一只手**（画面上出现第三条手臂），故改为"一手搭膝、一手持剑"——恰好两只手、轮廓清晰，且"剑握在画面右侧"的不变量继续成立。

| 时间 | 动作 |
|---|---|
| 0.00–1.20 | 呆滞：身体极缓地左右微摆（±2°），呼吸起伏，眼睛半睁、视线失焦 |
| 1.20–2.40 | 犯困：眼皮越来越沉，头一点一点往下垂 |
| 2.40–3.00 | 猛地抬头：惊醒，眨两下眼，甩了甩头发（发丝大幅滞后甩动） |
| 3.00–3.90 | 打哈欠：嘴张到极限、胸腔抬起、身体后仰 12° 再回弹 |
| 3.90–4.80 | 揉眼：用手背蹭眼睛，肩膀耸一下，鼻子皱一下 |
| 4.80–5.50 | 又困：头再次垂下，裙摆无力垂落，抱住膝盖的手松了松 |
| 5.50–6.00 | 强撑：抬头，眼神重新聚焦，抱膝的手收紧，姿态回起点 |

**接缝**：静默。6.00s 回到抱膝姿态与头部抬起角，与 0.00s 对齐。
**辨识锚**：抱膝蜷缩 + **瞌睡点头** + 打哈欠。全靠这三个身体信号辨识，不依赖任何外物。

---

### ⑤ 完成 `complete` — 静默闭合 / 3.4s / 102 帧

**初始姿态**：站立悬浮，**右臂（画面左侧）高举过头、张开手掌欢呼**，左臂（画面右侧）垂下握剑，下巴微抬，眼神亮晶晶（有底气的期待），笑出声。

> 修正记录：原设计为"双手背在身后挺胸"。实拍发现正面视角下"手在身后"会被生成模型直接丢臂（表现为缺一只手），故改为**高举右臂欢呼**——这是正面可见、手臂轮廓清晰的姿态，同时保留"挺胸 + 亮眼"的情绪强度。

| 时间 | 动作 |
|---|---|
| 0.00–0.50 | 深呼吸挺身，肩膀打开，剑在身侧轻晃 |
| 0.50–1.00 | 起跳：剑举过头，向上跃起 30% 身高，翅膀全展，裙摆飞扬 |
| 1.00–1.70 | 空中：**转体半圈 180°**，星星眼，笑出声，翅膀拍合一次 |
| 1.70–2.20 | 落地：屈膝缓冲压扁 12%，头发裙摆滞后 0.30s 甩落 |
| 2.20–2.90 | 站稳：伸展，翅膀收拢，星星眼渐变回普通笑眼 |
| 2.90–3.40 | 回初始：高举的右臂（画面左侧）落回肩侧，剑在左手（画面右侧）垂稳，挺胸，裙摆摇一下 |

**接缝**：静默。3.40s 回到起点姿态，星星眼已退完。
**辨识锚**：跃起 + 空中转体 + 星星眼。全桌宠唯一的跳跃，也是唯一的"高度变化"。

---

### ⑥ 出错 `error` — 事件闭合 / 4.6s / 138 帧

**初始姿态**：站立悬浮，右手（画面左侧）叉腰，下巴微抬，左手垂握剑于画面右侧，身姿挺拔；**身前浮着一枚她自己的法阵**，正缓缓自转。

| 时间 | 动作 |
|---|---|
| 0.00–0.45 | 得意：身体左右轻摆两下，裙摆随之晃，法阵正常旋转 |
| 0.45–0.90 | 法阵失控：字符乱转、由青转红、猛然炸散成碎片（炸散的是法阵） |
| 0.90–1.70 | 慌乱：身体被冲击推得后仰，双手在身前乱挥 4 次，剑脱手飞出画面右上角 |
| 1.70–2.50 | 剑回：从画外飞回，"啪"地插在她身侧，她定格愣住 0.4s（喜剧停顿） |
| 2.50–3.50 | 沮丧：叉腰的手垂下，肩膀垮，头低 15°，裙摆垂落，眼眶泛红，咬住嘴唇 |
| 3.50–4.20 | 自我重建：她闭眼深吸气，**身周重新浮起一枚小法阵**，法阵旋转着把散乱的气流聚拢，她的身体自下而上重新凝实（自身形变） |
| 4.20–4.60 | 回归：小法阵缩入她掌心消失，她睁眼，重新叉腰挺胸，身姿再次挺拔 |

**接缝**：事件。4.60s 回到起点姿态。接缝被叙事成"法阵失控 → 重新凝聚"，法阵是唯一在场的新元素。
**辨识锚**：法阵失控 + 剑脱手 + 沮丧 + 自我重建。
**禁忌**：不做哭嚎、不做愤怒红脸。桌宠是陪伴不是惩罚。

### ⑦ 拖拽 `dragging` — 静默闭合（往复摆）/ 5.0s / 124 帧

**初始姿态（v18 交付版）**：被用户拎着悬空——**右手（画面左侧）高举过头**（手被"握住"），身体松弛下垂、脊椎柔曲、头微侧、**半阖眼 + 闭唇浅笑**，**双腿并拢微屈**、脚尖轻点向下，翅膀**半开下垂如披风**，**左手（画面右侧）低垂握水晶剑、剑尖朝右下**。**头发全程重力下垂**，披在两肩与背后、发梢朝下，**头顶上方只有那只手，没有任何上飘的发团**。

> **第 10 轮改写**：用户明确要求「不要头发飞起来、要做得更优雅」。v17 的辨识锚是「头发全部向上飘 + 腿蜷成猫团 + 嘴张成小圆」——那是**慌乱挣扎**的观感，不是优雅。故整条重做：换参考帧（codex 重出）、换提示词、换动作结构。

| 时间 | 动作 |
|---|---|
| 0.00–1.20 | 轻轻提起：身体上提约八分之一身高后回落，**头发与裙摆滞后半拍才跟上来**（优雅的关键＝跟随延迟，不是拉伸） |
| 1.20–3.50 | 钟摆：先**向左倾**（头和举起的手去画面左边、并拢的脚留在中间，明显斜着），再**向右倾**（头和手去右边、脚留在中间）；**全程高度不变** |
| 3.50–5.00 | 回正：摆回中位，速度减慢，头发裙摆轻轻收住，停在 Picture 1 姿态 |

**接缝**：静默。5.00s 回到中位垂悬，剑在手里、倾角与 Picture 1 一致（96px 显示尺寸下差异像素 0.00%）。
**辨识锚**：悬空垂吊 + **头发全部向下垂** + 明显的左右钟摆 + 平静半阖眼的从容神情。

**历史版本（v17，2026-10-22 之前交付，已被 v18 取代）**：头发**全部向上飘起**、双腿蜷起像被提起来的猫、翅膀半张、嘴张成小圆；3 拍为「上提拉伸 → 左右钟摆 → 回正」。辨识锚是「悬空 + 头发上飘 + 钟摆」。

**原设计（v2，5 拍，已废弃）**：竖向拉伸 8% → 摆到左极限 −20° → 剑脱手但被细光带拉住（连着腕部）悬在下方晃动 → 摆到右极限 +20° → 摆回中位并过冲 3°。

### ⑧ 休眠 `sleeping` — 静默闭合 / 8.0s / 240 帧

**初始姿态**：悬浮侧躺蜷缩，**抱着她的水晶剑当枕头**（横抱在怀里），双手环住剑身，双腿蜷起，双眼闭合，脸颊泛红。

| 时间 | 动作 |
|---|---|
| 0.00–1.80 | 深睡呼吸：胸腔起伏（2s 吸 + 2s 呼），身体缩放 1.00↔1.03，翅膀随之微动 |
| 1.80–2.80 | 翻身：侧躺 → 抱膝，剑被抱到胸前（180° 大幅翻转，加速后减速） |
| 2.80–4.20 | 抱膝续睡：下巴搁在剑柄上，肩膀随呼吸起伏 |
| 4.20–5.20 | 咂嘴 + 轻轻哼一声 |
| 5.20–6.20 | 反向翻回侧躺（与 1.80–2.80 镜像），剑重新横抱回怀里 |
| 6.20–8.00 | 回到起点继续睡，呼吸相位与 0.00s 对齐 |

**接缝**：静默。8.00s 回到侧躺抱剑姿态，呼吸相位对齐。
**辨识锚**：闭眼 + 蜷抱剑 + 冷色调（降饱和 10%）。剑抱在怀里当枕头。

## 5. 状态切换策略

不引入新元素后，"用气泡爆开遮住姿态跳变"这类手法不可用了。改用三种**由她自身完成**的遮蔽：

| 策略 | 做法 | 适用 |
|---|---|---|
| **动作接续** | 下一态首帧 = 上一态末帧的自然延续 | idle→thinking、thinking→calling_tool、dragging→idle、idle→sleeping |
| **甩身遮蔽** | 切换瞬间她快速转身 / 甩发 / 甩裙摆，用这一拍的大幅运动 + 一帧运动模糊遮住姿态跳变 | idle↔waiting、idle↔sleeping、complete→idle、error→idle |
| **法阵遮蔽** | 法阵炸散/生成的过程本身覆盖跳变 | calling_tool→error |

### 转场表

| 转场 | 时长 | 策略 | 手法 |
|---|---|---|---|
| 待机 → 思考 | 250ms | 接续 | 站立悬浮中直接收腿盘起，前倾托腮 |
| 思考 → 调用工具 | 300ms | 接续 | 托腮的手放下抓起剑，身前浮出法阵 |
| 调用工具 → 完成 | 150ms | 接续 | 剑停住、法阵缩回 → 右臂高举欢呼挺身 |
| 调用工具 → 出错 | 180ms | 法阵遮蔽 | 法阵失控炸散的过程本身遮住跳变 |
| 出错 → 思考 | 400ms | 接续 | 重建完成后顺势收腿盘起 |
| 完成 → 待机 | 400ms | 甩身遮蔽 | 落地后顺势甩身转头，一拍运动模糊 |

## 7. 易错点清单

1. **拖拽时头发下垂** — 惯性方向错，必须向上飘。
2. **偷偷加回道具** — 去掉坐具后容易顺手加个垫子；判定标准见 1.2。
3. **出错态的事件闭合没有法阵** — 法阵炸散与重建是本态的叙事支点，缺了就成了普通静默闭合。
4. **甩身遮蔽的甩动幅度不够** — 幅度小于姿态跳变幅度就遮不住，会露出跳变。
5. **闭合点速度不归零** — 静默闭合处顿挫。
6. **发丝没有滞后** — 整张图一起动，贴纸感。
7. **法阵没有"从她身上生出来"的动画** — 突然出现在画面里会像贴纸，必须有生成/消散过程。
8. **休眠没有真正的闭眼图层** — 半闭会读成没睡着。
9. **刘海覆盖差异会改变脸部"观感"大小** — 同一头身比例下，think 的刘海没盖住额头，整张脸是连续明亮面形，加上头朝镜头偏，脸看起来明显比其它态大。**这不是缩放算错**（IPD 实测 142.0 落在 138–154 群体区间内、居中，头身比准确），但观感上就是"脸大"。曾尝试用等比缩放压掉它（165 → 145.2 → 127.8），但那样 think 会比其它态明显小，**最终按需求方决定收回例外，八态一律 165（脸一样大）**。**关键认知：等比缩放不改变「脸相对头」的比例**，只能改"该态相对其它态"的大小；真要压这一观感差，只能重出 think 帧让刘海盖住额头（改脸型而非改缩放）。

## 9. 循环动画视频交付（2026-10-21）

用 `normalized-uniform/` 的 8 张统一画布绿幕图作参考，各生成一段**可无缝循环**的动画视频。

### 规格

| 项 | 值 |
|---|---|
| 模型 | `MiniMax-H3-Max`（约 20 秒出片，走账号积分） |
| 模式 | **首帧 + 尾帧关键帧（FL2VA）**，首尾用**同一张图** |
| 分辨率 | 768P，实测 **768×768 / 比例 1.000** |
| 比例 | 1:1（随参考图） |
| 时长 | idle 5s / think 5s / tool 5s / wait 6s / done 5s / error 5s / drag 5s / sleep 8s |
| 声音 | 静音（`overall_soundscape: N/A`、`non_diegetic_music: N/A`） |

### 为什么用「首尾同图」锁循环

桌宠每态必须无缝循环，**起始帧 = 结束帧**。把同一张图同时作为首帧和尾帧，模型被强制在两端回到同一姿态，接缝就落在设计稿指定的"闭合点"上，循环不靠提示词碰运气。
代价：首尾完全静止的一帧可能让模型偷懒，所以提示词里仍逐态写明「回到起始姿态、末帧与首帧一致」。

### 提示词要点（8 条已固化在 `video-prompts/`）

1. **首尾对齐行**（FL2VA 头行）：`Picture 1 … 0.00-second` / `Picture 2 … X.00-second`，并注明 Picture 2 与 Picture 1 是同一张图。
2. **绿幕不可变**：全程均匀 `#00FF00`，无渐变、无地面、无地平线、无投影、无光晕。
3. **镜头锁定**：固定机位、全身景别、角色位置与大小与参考帧一致，无推拉摇移、无变焦、无切镜。
4. **角色一致性锁**：人形双腿无鱼尾、恰好两臂两手、左手（画面右侧）持水晶剑且剑不横跨身体、银蓝长发为**分开的 S 形波浪**（显式排除螺旋团）、鳍耳与蓝紫渐变羽翼齐全。
5. **动作拍点压到 3 个**（记忆经验：5 秒塞 6 个拍点会被静默丢弃），其余写成同一动作的修饰。
6. **回位收尾**：每条最后一句都写「回到起始姿态，末帧与首帧一致，循环无缝」。

### 第 6 轮：面板几何重做 —— 宽幅横牌 + 水属性艺术字（2026-10-21）

**需求变更（用户）**：① 蓝色面板要**变大**且必须是**宽幅横牌**；② 字体要**符合水属性的艺术字体**；③ **面板必须装下所有字体**；④ **人物必须由 codex 一次性生成**（明确否决像素合成路线）；⑤ 无光晕约束继续生效。

**先算清几何硬边界**（写进 `%TEMP%\measure_frame2.py`）：

- 768p 面板尺寸 = 源图面板宽 × k × 768/1978，其中 k = 165 / 脸框宽。

#### think 的病因：提示词要求「左手握剑」，但参考帧里剑根本不在她手里

把参考帧放大看得很清楚：她**双手都托在腮上**（掌心在颊下、手指在颧骨旁），而那把水晶剑是**插在身旁右侧地上**的——剑柄带宝石在右上、剑尖朝左下。她**从来没有握过剑**。

而 v2 提示词第一句就写 `She holds her slender crystal sword in her left hand, which is on the RIGHT side of the image`，动作段又写 `both hands cupping her own cheek`——**左手同时要握剑和托腮**。模型面对这个矛盾，两个都做不好，于是验收判「托腮/点下颌动作没做出来」。

另外 v2 的动作脚本有 **5 个拍点**（点颊 / 敲节拍 / 换思路 / 顿悟 / 收），远超模型在 5 秒内的承载能力。

**v17 改法**：剑改写成「插在身旁地上、剑柄在右上、剑尖朝左下、**她不握剑也不去握**、全程一动不动」；拍点压到 3 个。

v17 结果 **5/6**，唯一不通过是「角色全程保持双手托腮」，理由「中途变换了手部动作」——但这条和「用一根手指轻点脸颊」**本身互斥**：掌心贴着腮就不可能用手指去点同一侧的脸，抬手点 = 手离开腮。

**v18 改法（把物理矛盾从提示词里消掉，而不是去改验收标准）**：点腮改成**掌心不动的指尖点**——「the palm of that hand stays pressed against her cheek and never leaves her face, only the fingertip bends and straightens once」；POSE 段补「Both of her PALMS stay pressed against her own cheeks for the whole clip and never leave her face」；闭眼那拍的「头沉进手掌」改成「头微微往下压一点点」，避免模型把手往下挪。

### 踩坑

- **账号积分不足会 402**：首次提交 8 段全部返回 `code 402 insufficient account credits`（H3 系 5s 需 347 分 / 6s 416 / 8s 555，8 段约 3053 分），**零任务创建、零扣费**。`MiniMax-Hailuo-2.3` 走 Token Plan 额度可绕过，但不支持尾帧模式（就没法用同图硬锁循环）、时长只能 6/10 秒。

- **`mcode-tools` 是 `.cmd` 转发器**，从 Python `subprocess` 直接调用会把参数改写（报 `unknown command 'mcode-tools'`）；改由 PowerShell 直调。

### 第 8 轮新增的踩坑

- **codex 是逐像素照抄参考图的**：`layout-guide.png` 里画成什么样，出来就是什么样。提示词里的「水属性艺术字」「宽幅横牌」这类措辞**改不动面板长相**。要改面板长相，唯一可控的杠杆是**重画参考图**。这是本轮最重要的机制发现。
- **给字体形容词没用，要给笔触几何**：v15 写 `SEA-WATER-STYLE HAND-LETTERED SCRIPT / strokes are rounded and flowing` → 出来是印刷黑体（编号清单判「常规印刷体非流水书法感」）。v16 改成 `strokes swell THICK where the brush pressed down and taper THIN where it lifted / the stroke ends come to a fine point / the horizontal strokes bow upward like ripples` → 出来是真毛笔书法。**落笔粗细、收锋、笔画末端形状、横画弧度、整体笔势**这五项才是模型能执行的东西。
- **「ONE single soft white」这类均匀填色措辞会把字推向印刷体**：想得手写感就别强调颜色单一均匀。
- **防乱字的否定项会把字推向"工整标准字形"**：`never broken, never split` 要留（防缺笔断字），但得放在句尾，别让它主导整段。
- **像素脚本的「文字越界」判据是单向的**：它只看框内像素的 bbox 算 margin，**报"0 帧越界"不等于留白宽裕**（v15/v16 的文字其实都贴到净蓝底边缘，上留白仅 1 px）。而且它按"最差值严格小于"更新、**平局取首帧**，真正的 worst 帧可能被前面的帧盖掉。
- **要判"文字有没有压到花边"，必须先分离静态文字与移动的剑**：用**时间方差**——文字静止（std < 2.5）、剑在动（std ≥ 2.5）。再把蕾丝环向内**膨胀 3 px** 剔掉环与蓝底之间的**过渡亮线**（那几行会被误判成文字），才量得到真实字形 bbox。本轮结论：v15/v16 文字膨胀 1 px 后与环求交 = **0 像素**，都没压到花边。
- **`$ErrorActionPreference='Stop'` 会让 ffmpeg 写到 stderr 的启动横幅变成终止性 `NativeCommandError`**，直接把循环打断。跑原生命令时别设 Stop，或把 stderr 重定向到文件（`*> $log`）。
- **ffmpeg 剥音轨用 `-c:v copy -an`**，不重编码视频、画面码流逐字节保留，8 条一起跑不到一分钟。
- **归一化的脸框约定必须与全组一致**：旧八态的 `FACE_BOX` 是「挂机态脸框相对双眼中点的偏移」，反推出的真实肤色框是 `FACE_BOX × 0.88`（实测 0.76~0.96）。换新帧时若误用完整肤色框当脸框，归一化后眼距会掉一整圈。配合 `SIDE = 2·k·(1254 − 脸心x) ≤ 1978` 的画布预算，本轮推出**脸框宽必须 ≥ 142**，取 142 后 tool 眼距 123.0 → 141.3（挂机态的 98.1%），老问题一次修掉且画布未破、其余七态逐字节不变。

### 第 9 轮新增的踩坑

- **动手前必须把参考帧放大读一遍**：think 卡了两轮的病因，v2 提示词写「左手握剑」，而参考帧里**剑是插在身旁地上的、她双手都在腮上**——提示词和参考帧打架，模型两个都做不好。**写提示词前先确认参考帧里道具到底在谁手里**，否则再好的措辞也白搭。

- **动作幅度要用双端锚点写，并显式排除替代解释**：drag v17 把摆动写成「头和举起的手走到左边、蜷起的脚留在中间，明显斜着而不是直的」，并补一句「全程高度不变、只有侧倾在变」——不补这句模型会把侧倾理解成下坠。实测摆幅 26px → 86px。

- **`-map 0:v` 与 `-filter_complex` 同时用会多出一条视频流**：必须给 filter 输出打标签并 `-map "[v]"`。

- **判定"头发有没有上飘"要给空间判据**：量「脸框以上那条带子」的非绿像素与**最长水平连续段**——旧版发团能把整幅 768 宽铺满（最长横段 768），新版只剩举起的手（317）。
- **归一化脚本要从"统一画布"倒推验收**：新脚本跑旧八态帧，必须能复现 README 里的 k 值（1.0510 / 1.1702），否则口径就是错的。

## 第 11 轮 · 八态去绿幕 → 透明背景（2026-10-22）

### 目标与约束

把 `work/videos\final\pet-<state>.mp4`（绿幕母版）转成**带 alpha 的透明背景视频**，8 条全交。

硬约束：① 768×768 / 24fps / 无音轨 / 与母版同画布；② **边缘不得残留绿幕色**；③ 循环接缝仍要闭合；④ 验收必须**像素级 + 真实消费者端**双证据（`videos_understand` 会自相矛盾，本轮又用浏览器做了独立复核）；⑤ 不改写绿幕母版，透明版另存并列登记。

### 一、封装格式选型（为什么最后选 VP8 + alpha WebM）

本机 ffmpeg 7.1（`imageio-ffmpeg` 自带）能写出 alpha 的封装只有四种，逐个实测：

| 封装 | alpha 轨 | 24 帧体积 | 折算 124 帧 | 结论 |
|---|---|---|---|---|
| `libvpx-vp9` + `yuva420p` | **写不进**（输出仍是 yuv420p） | — | — | 弃用 |
| `libvpx`(VP8) + `yuva420p` | ✓ `alpha_mode=1` | 519 KB | **2.6 MB** | **选中** |
| `libaom-av1` | **丢** | — | — | 弃用 |
| `prores_ks -profile:v 4444` | ✓ `yuva444p12le` | 9.2 MB | 47 MB | 备选（体积 18 倍） |
| `qtrle` | ✓ `argb` | 10.2 MB | 52 MB | 备选 |
| `-f apng` | ✓ RGBA | 8.3 MB | 42 MB | 备选 |

VP9/AV1 丢 alpha 的根因：FFmpeg 的 `libvpxenc` **只给 VP8 设 `is_alpha`**（`x->vp8_cfg.is_alpha = 1` 写在 VP8 分支里），VP9 分支永远不设——所以哪怕编码器声明支持 `yuva420p`，alpha 也不会进容器。

**VP8+alpha 是唯一"小 + 浏览器原生 + 可验证"的组合**。Chromium 从 2016 年起就支持 WebM 的 `alpha_mode`（VP8 alpha），这正是桌宠这类场景的标准做法。

### 二、抠像算法（`tools\green_to_alpha.py`）

不走 ffmpeg 的 `colorkey/chromakey`，而是**逐帧物理抠像**：

1. **估背景色**：取"绿意像素"（`g>150 且 r<90 且 b<90`）的中位数 → 实测 `(0, 244, 0)`。
2. **取种子**：`d = |obs − bg|` 的最大通道差 > 50，且 **`green_dom = G − max(R,B) < 12`**。
3. **传播前景色**：把种子的颜色向外迭代膨胀 14px，得到每个像素的"干净前景色" `fg`。
4. **解算 alpha**：按合成公式 `obs = a·fg + (1−a)·bg` 反解 `a = ⟨obs−bg, fg−bg⟩ / |fg−bg|²`，再套软阈值 `a = clip((t−0.04)/(0.96−0.04))`。
5. **上色**：透明区 RGB 置 0（防 4:2:0 色度下采样把绿渗回来），**过渡带与实心区一律用 `fg`**（不是观测色）。
6. **despill**：实心区 `G − max(R,B) > 30` 时把 G 压到 `max(R,B) + 0.25×余量`。

#### 三处关键修正（都是踩出来的）

- **① 绿染像素不能当种子。** H.264 压缩会在角色轮廓上留下 1–2px 的"绿染"抗锯齿像素（实测绿 excess 中位 ~160），它们与背景色的最大通道差 > 50，若直接当种子会把绿顺着传播灌进整条边带——**过渡带绿 excess 均值一度高达 142**。实测这些像素腐蚀一次就掉 95%（是薄带不是实心块），所以排除它们不会打洞。改成按 `green_dom` 过滤后，过渡带绿 excess 降到 **−7**。
- **② 实心区要用 `fg` 而不是观测色。** 种子像素 `fg == obs` 没差别；但轮廓上那些**带一点绿、因 `green_dom` 超阈值被排除出种子**的像素，投影算出来 `a≈1` 会被判成"实心"，若用观测色就把绿味固化了。改用 `fg`（传播出来的干净色）后，这批像素的绿 excess 从 **~110 降到 0**。
- **③ 种子阈值 `T_SEED` 从 25 降到 12。** `green_dom ∈ [12,25)` 的像素（角色青色羽翼与绿幕的混合色）原本被当成"纯前景"，会带着绿味当实心色。降到 12 后它们改走正常抠像路径：alpha 略微变淡、颜色换成干净的传播色。

#### A/B 实测（6 帧/态，绿像素 = 实心区且绿 excess>12）

| 状态 | T_SEED=25 | T_SEED=25 + 用 fg | **T_SEED=12 + 用 fg** | 重建误差代价 |
|---|---|---|---|---|
| pet-done | 7573 | 7612 | **14** | 2.774 → 2.835 |
| pet-idle | 5670 | 5641 | **3** | 0.528 → 0.563 |
| pet-tool | 4979 | 4906 | **18** | 0.548 → 0.578 |
| pet-think | 2683 | 2632 | **6** | 0.429 → 0.446 |

`T_SEED` 再降到 0 会破坏抠像（背景被当前景，全透率从 81% 崩到 91%、重建误差 16.3），**12 是安全边界**。

### 三、编码参数

`-c:v libvpx -pix_fmt yuva420p -b:v 8M -auto-alt-ref 0 -qmin 4 -qmax 48 -lag-in-frames 0`

- **不能用 CRF**：本机 libvpx 的 `-crf` 是坏的——crf 4 / 10 / 16 输出**字节完全相同**（129 KB），PSNR 只有 22.5 dB。只能用 `-b:v` 目标码率。
- **码率扫描**：1M→1.8MB/条、2M→2.7MB、4M→4.0MB、8M→6.5MB、16M→7.1MB。8M 时 RGB PSNR **38.28 dB**、回合成误差 0.832（无损抠像真值是 1.05），已与无损持平；16M 只多 0.6MB 换 +1.6dB，不划算。
- **循环闭合**：源 MP4 的末帧是首帧的"H.264 重编码副本"，像素并不完全相同（首尾 RGB 差 mean 2.99），抠像会把这点差异在轮廓边缘放大成 alpha 跳变（alpha 最大差 205）。做法是**抠像后直接把末帧的像素换成首帧**，并用 `-force_key_frames expr:gte(n,N-1)` 让末帧成为 I 帧 → 首尾解码后**逐像素完全相同**（全分辨率 rgba mean 0.000 / max 0）。

### 四、验收（8 条全过）

| 判据 | 结果 |
|---|---|
| 容器 alpha 轨 | 8/8 `alpha_mode=1` |
| alpha 分布 | 全透 77.7%–87.8% / 全不透 11.0%–19.7% / 过渡带 0.8%–2.8% |
| 过渡带绿 excess 均值 | −111 ~ −117（Chromium 端实测） |

### 五、本轮踩坑

- **ffmpeg 解 VP8 alpha 必须显式 `-c:v libvpx`**：原生 `vp8` 解码器**会丢掉 alpha 轨**（容器 `alpha_mode=1` 还在，解出来是不透明 yuv420p）。第一版验收脚本因此报"alpha 全 255"的假象。
- **抽帧验 alpha 必须显式 `-pix_fmt rgba`**：PNG 默认 rgb24 会静默丢 alpha。
- **VP8 alpha 的 4:2:0 色度下采样会把边缘色相拉绿**：透明区 RGB 必须置 0，否则下采样时透明像素的绿会和边缘像素的平均，把绿渗回角色边缘。
- **`<video>` 在这个内置浏览器里不出画**：`onloadeddata` 触发了但合成层没更新。改成 `canvas.drawImage(video)` 抓帧才拿得到真实像素；纯 `file://` 页面还会让 canvas 被污染，`getImageData` 抛 SecurityError——**必须起一个本地 http 服务**做同源。
- **`imageio-ffmpeg` 的 ffmpeg 输出里 alpha 轨在 `alpha_mode` 字段里**，用 `ffmpeg -i` 的 stderr 就能确认，不必装 ffprobe。
- **母版 MP4 的首尾帧本来就不完全相同**（H.264 重编码），任何"首尾闭合"的判据都应该在**解码后**而不是编码前量。
