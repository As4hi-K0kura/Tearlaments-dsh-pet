## 一、八态优先级判定

### 1.1 dsh-pet 的模型（照搬的部分）

| dsh-pet 概念 | 规则 | 出处 |
|---|---|---|
| 事件档位（tier） | `WORK_STATUS_STATES = ['thinking','working','result','waiting','success','error']`，**索引即档位，顺序即语义，新档只能追加到末尾** | `src/shared/work-status.ts` |
| 事件动画 | **不进随机链**，只由事件显式触发；同档位多候选时档内随机、尽量不连播同一个 | `assets/config.jsonc` |
| 随机链 | 每个动画播完按权重选下一个；`animationWeights` + 各分类 weight 合计 100 | `assets/config.jsonc` / `src/shared/pickers.ts` |
| 用户交互优先 | 位置/抛掷指令在用户按住宠物时**整拍丢弃** | `src/client/pet.ts` |
| 占用锁 | 被第三方占用时冻结自播动画、忽略**自动**来源（余额/工作状态），用户主动仍生效 | `src/shared/state.ts` |
| 终态优先 | 气泡优先级：终态任务 > 碎碎念/对话 > 余额 > 非终态任务 | `src/client/pet.ts` |
| 切换无空白帧 | 双缓冲交叉淡入；被换下去的视频必须掐掉 `onended`，否则会误触发下一段 | `src/client/pet.ts` |

### 1.2 本项目的八态优先级

优先级分两套，互不替代：

- **档位（tier）** = 事件语义顺序，沿用 dsh-pet 的编号，保证与宿主会话事件一一对应。
- **抢占优先级（priority）** = 「谁能打断谁」，与档位顺序无关。

| 优先级 | 状态 | id | dsh 档位 | 触发源 | 抢占规则 |
|---|---|---|---|---|---|
| 9 | 拖拽 | `dragging` | —（用户物理） | USER | **硬切 120ms，抢占一切**，任何态立即让位 |
| 3 | 完成 | `complete` | 4 success | EVENT | 终态：不被非终态打断，只被拖拽打断 |
| 3 | 出错 | `error` | 5 error | EVENT | 同上 |
| 2 | 调用工具 | `calling_tool` | 1 working | EVENT | 可被 3/9 打断 |
| 1 | 思考 | `thinking` | 0 thinking | EVENT | 可被 2/3/9 打断 |
| 1 | 等待 | `waiting` | 3 waiting | EVENT | 同上 |
| 0 | 待机 | `idle` | —（随机链底座） | CHAIN | 任何时刻可被打断 |
| 0 | 休眠 | `sleeping` | —（随机链） | CHAIN | 最低，被任意任务态打断 |

> dsh-pet 的档位 2（`result` / tool-result 整理）本项目没有对应状态，**保留编号占位**，
> 以免日后新增时把既有档位含义错位。

### 1.3 判定规则（`StateMachine.request`）

```
USER     → 永远生效（用户交互优先）
FALLBACK → 永远生效（事件态播完回落 idle，不算抢占）
EVENT    → 只有 priority >= 当前态 才抢占，否则**丢弃**
CHAIN    → 同 EVENT，且只能抽到 chainEligible（idle / sleeping）
占用锁   → 锁定时 EVENT / CHAIN 一律不响应，USER 仍生效
```

### 1.4 转场表

直接采用 `states.json` 的 13 条转场（`continue` 接续 / `bodyMask` 甩身遮蔽 /
`arrayMask` 法阵遮蔽 / `hard` 硬切），运行时按 `strategy` 决定是否瞬切：
`hard`（任意 → dragging）零毫秒硬切，其余 120ms 交叉淡入。

## 二、脸部归一化：为什么是「脸宽 + 脚底线 + 脸心」三个锚

### 2.1 问题

八态素材在 768×768 画布里**占位差异巨大**（实测内容高度 43.2%–96.4%），
直接放进同一个窗口，桌宠切状态时会在 1.4 倍的尺度间跳。

dsh-pet 的做法（`scripts/normalize_step03.py`）是**站立高度**归一 + 脚底线对齐 +
水平居中取非透明像素 x 的**中位数**。本项目不能照抄：

| 锚 | dsh-pet | 本项目 | 原因 |
|---|---|---|---|
| 尺度 | 站立高度 | **脸宽** | `thinking` 盘腿 / `sleeping` 躺下 / `dragging` 悬空，这三态**根本没有站立高度** |
| 水平 | 内容 x 中位数 | **脸心 x** | 内容并集会被剑/法阵/翅膀拉偏；脸心是稳定的角色锚点 |
| 垂直 | 脚底线 | **脚底线**（`dragging` 例外） | 盘腿/躺下时「脸心到脚底」的距离本就该变，强行对齐脸心会把身体拉长或让人浮空 |

脸宽口径与本项目 `normalized/` 管线一致（复用 `detect_ipd.find_face_blob`），
与设计稿「八态脸宽一律 165」同源。

### 2.2 闭式迭代（关键）

源帧上量到的「可见肤色块宽度」与「归一化后应有的宽度」之间有**系统性偏差**：
头发遮脸、手掌贴脸时，肤色块会变形。实测首帧口径的脸宽极差达 1.40 倍（65–91px）。

所以尺度不按源帧估计确定，而是**在产物图集上复测再回修**：

```
k₀ = 目标脸宽 / 源帧实测脸宽
构建 → 在输出图集上用同一套判据复测脸宽 → k ← k × (目标/实测)^0.7 → 重建
收敛判据：最差偏差 ≤ 6%；多轮取偏差最小的一轮
```

实测：第 1 轮最差偏差 26.8%（drag 52px / think 47px），第 2 轮收敛到 **4.9%**。

### 2.3 脸部检测判据（踩过的坑）

窗口内「最大肤色块」会抓到**手**（手也是肤色，有时还比脸完整）。有效判据是三条同时成立：

1. 肤色块宽高比 ∈ [0.78, 1.55]（排除细长的手臂/腿）
2. 块中心离已知脸心 ≤ 30px（脸不会乱跑，手会）
3. 块宽与基准脸宽相差在 [0.65, 1.45] 倍内（排除指节等小块）

另外两个坑：窗口坐标是**局部**的，要换算回全局再与脸心比；块被窗口切过时会低估宽度，
所以宁缺毋滥——该帧跳过而不是拿一个偏小的值。

### 2.4 归一化实测结果（在**产物图集**上复测）

公共画布 391×395，目标脸宽 41px，公共脚底线 y=370.78，公共脸心 x=191.21。

| 状态 | 脸心 x | 脸心 y | 脸宽（产物） | 内容原点 |
|---|---|---|---|---|
| idle | 191.2 | 176.5 | 40.5 | [80, 4] |
| thinking | 191.2 | 260.8 | 42.0 | [109, 205] |
| calling_tool | 191.2 | 183.1 | 41.0 | [98, 117] |
| waiting | 191.2 | 220.6 | 41.0 | [79, 162] |
| complete | 191.2 | 203.0 | 42.0 | [4, 41] |
| error | 191.2 | 189.7 | 40.0 | [89, 118] |
| dragging | 191.2 | 192.5 | 39.0 | [51, 76] |
| sleeping | 191.2 | 216.9 | 41.0 | [54, 158] |

- **脸心 x 极差 0.00 px** —— 八态水平完全对齐（这是硬对齐，不是近似）。
- **脸宽极差 3.0 px（7.4%）**，对目标 41px 的最大偏差 ±4.9%。
- **脸心 y 不归一**（176.5~260.8）：盘腿 / 站立 / 躺下姿势不同，脸的绝对高度本就该不同，
  强行对齐会把身体拉长或让人浮空。垂直锚是脚底线。

## 三、图集方案

### 3.1 为什么不用视频

JavaFX 的媒体管线**没有 alpha 通路**：VP8/VP9 的 `alpha_mode=1` 轨会被静默丢弃，
`MediaView` 只能拿到不透明帧。所以这 8 个透明 WebM 在 JavaFX 里放不出来。
（dsh-pet 用 WebM 是因为它的宿主是 Chromium/Electron，浏览器原生支持 WebM alpha。）

图集方案的收益：一态一张 PNG 纹理，帧切换 = 改 `ImageView.setViewport()` 的矩形，
**零 GPU 重传、零 GC 抖动**。

### 3.2 布局

- **公共画布**：八态共用一套画布坐标（本次 391×395），切换状态时角色不发生位移。
- **每态一张网格图集**（12 列），格子 = 该态变换后内容并集 + 2×4px padding。
- **manifest.json** 记录每态的格子位置（`cellX/cellY`）、尺寸、帧数、fps、优先级、档位，
  运行时只按清单切帧，不再知道任何归一化参数。

```
canvas: { w, h, groundY, faceCX, faceWidth }
grid:   { cols, padding }
chain:  { weights: {idle:65, sleeping:35}, sleepAfterIdleLoops:3 }
states: [{ id, atlas, cols, rows, fw, fh, cellX, cellY, frames, fps,
           priority, closure, faceWidth, faceWidthOut, faceCenter,
           contentOrigin, headHeight, scale, groundAligned, ... }]
transitions: [ ... 来自 states.json 的 13 条 ... ]
```

### 3.3 帧率与体积

源 24fps → 输出 **12fps**（桌宠动作慢，帧数与显存直接减半）；帧数 = 源帧数 − 1
（末帧是首帧副本，为锁循环而替换，剔除后一轮无缝闭合）。

八态图集合计约 **46MB PNG**；GPU 上 RGBA 约 180MB，所以运行时**按状态懒加载**
（`AtlasPlayer` 后台线程加载，未就绪时视图透明）。

## 四、JavaFX 运行时

```
src/main/java/app/pet/
  PetApp.java        Stage（TRANSPARENT/UNDECORATED/ALWAYS_ON_TOP）、交互、DSH 接线
  PetManifest.java   清单解析（Gson）
  AtlasPlayer.java   图集播放器：懒加载 + viewport 切帧 + AnimationTimer 帧驱动
  StateMachine.java  优先级状态机（抢占判定、随机链、占用锁）
  PetState.java      八态枚举（档位 + 优先级）
  DshClient.java     dsh-pet 宿主 HTTP 客户端（长轮询 /state + POST /pose/report）
  DshBridge.java     档位表 + 后台轮询线程 + 锁/位置叶子消费 + 端口发现
  Win32.java         JNA：点击穿透 / 不抢焦点 / 不进任务栏
```

要点：

- **帧驱动用 `AnimationTimer` 而非 `Timeline`**：素材 12fps、屏幕 60/120Hz，
  12 不整除 60，Timeline 固定 KeyFrame 会抖；帧号累加器把误差摊平。
- **切换用双缓冲交叉淡入**，被换下的视图隐藏，避免空帧。
- **点击穿透用 JNA 调 Win32**（`WS_EX_LAYERED|WS_EX_TRANSPARENT|WS_EX_NOACTIVATE`）。
  注意穿透与悬停检测互斥，所以做成可切换开关而不是常开。
- **拖拽**：按下即 `USER` 请求 → `dragging` 态硬切，切换时把内容原点挪回去避免跳位；
  松手回 `idle`。

### 4.1 显示尺寸规则

| 量 | 定义 | 取值（1440p 屏 / 150% DPI） |
|---|---|---|
| 角色高度 `contentHeight` | 画布像素，各态内容并集高度的最大值（= 373.9） | — |
| 目标高度 `baseDisplayHeight` | 角色在屏幕上的逻辑像素高，默认 `屏高×0.20`，夹在 190~340 | 288 |
| 缩放 `scale` | `baseDisplayHeight / contentHeight` | 0.7446 |
| 舞台尺寸 | `canvas.w×scale` × `canvas.h×scale` | 291×294 |
| 脚底线落点 | `stageY = 屏幕可视底 − groundY×scale` | 1116（脚底线正好在 1392） |

- **不能用格子高 `fh` 换算**（含 padding），也不能用画布高（是八态并集，尾部有留白）；
  统一用「角色内容高度」。
- 水平按**内容右缘**对齐屏幕右缘（留 24px），不是按画布右缘 —— 画布右侧是透明留白。
- 体型可在右键菜单切换（紧凑 / 标准 / 加大 = 0.72 / 1.0 / 1.35 倍基准高度），
  或启动时 `--height=<px>` / `--scale=<倍率>` 指定。

### 4.2 踩过的坑（v1 → v2）

| 坑 | 现象 | 根因 | 修法 |
|---|---|---|---|
| **缩放绕错中心** | 窗口里只剩一角碎片；换状态碎片位置还变；有时整只隐身 | `Node.setScaleX/Y` 绕**节点自身包围盒中心**缩放，不是绕原点。画布 Group 包围盒是 (76,0,315,383)（中心偏右下），缩放后整体位移 (+117.7,+96.5)，人鱼被挤出窗口 | 改用显式 `new Scale(s,s,0,0)`（pivot=画布原点）；点击挤压另用 `new Scale(1,1,faceCX,groundY)` 绕脚底，两者串成变换链 |
| **命令行参数读不到** | `--scale=` / `--height=` / `--shot=` 全部静默失效 | JavaFX 把 `--key=value` 解析成**命名参数**放进 `getNamed()`，`getUnnamed()` 里看不到 | 改用 `getParameters().getRaw()` 自己解析 |
| **自适应分支进不去** | 缩放恒为 1.0 | `scale` 初值写死 1.0，判据 `scale <= 0` 永远为假 | 初值改 0（= 未指定） |
| **切态隐身** | 切到未解码完的图集时宠物消失 1~2 秒 | 旧视图已淡出，新视图的图集还在解码，视图是空的 | 图集未就绪时**延后切换**（`pendingState`），保持旧画面；启动时后台 `preloadAll()` 预热全部图集（`--lazy` 可关，省约 200MB） |
| **非可缩放窗口改不了大小** | 体型菜单无效 | `setResizable(false)` 时 `stage.setWidth()` 被忽略 | 改用 `min=max=尺寸` 固定，仍可编程改大小 |
| **`Scene.snapshot()` 卡死** | 自检无输出 | Scene 作为根节点时边界计算不可靠 | 改成 `root.snapshot(params, null)` + 显式 viewport |
| **`Node` 没有 `getBoundsInScene()`** | 编译不过 | JavaFX 21 没有这个方法 | 用 `v.localToScene(v.getBoundsInLocal())` |

### 4.3 拖拽（漂移问题的三处根因与修法）

**现象**：拖动时角色相对光标漂移。

| 根因 | 说明 | 修法 |
|---|---|---|
| 状态切换用**内容包围盒角点**补偿 | idle 的角点是发梢、dragging 的角点是举起的手，两者差 (−29, +72) 画布 px = **57.8 逻辑 px**，一按就跳 | 改用**脸心**补偿：新脸心落在旧脸心的屏幕位置上 ⇒ 窗口位移 = (旧脸心 − 新脸心) × scale。脸心 x 八态一致（归一化硬保证），所以只有 y 需补（±11.9px） |
| **增量式跟随** `setX(getX()+delta)` | 任何状态切换位移/丢事件都会累积成漂移 | 改**刚体跟随**：按下时记 `grabDX = 光标x − 窗口x`，之后每帧 `setX(光标x − grabDX)`（绝对定位，不累积）。状态切换的补偿量同步修正 `grabDX`，否则会被下一帧覆盖 |
| 抓取点**无判定** | 窗口 391×395 里角色只占一部分，按在透明区也会把人鱼拽走 | 加**像素级命中测试**（`AtlasPlayer.hitTest`：按当前帧图集坐标取 alpha，>16 才算抓住） |

**松手**：按转场表 `dragging → idle = 300ms continue`（落地屈膝 + 甩头发）做交叉淡入，
顺带把「站直时头抬高 11.9px」化掉；`any → dragging` 保持 hard（0ms，抓取必须瞬时）。
接了 DSH 之后，松手的目标不再是固定 `idle`，而是**恢复当前档位**（非终态）或回落待机
（终态/无档位）—— 见 §5.4。

**自测**（`--driftest`，用合成坐标走一遍按下→移动→松开，**不碰真实鼠标**）：
判据是「脸心屏幕位移 == 光标位移」。

```
[drift] 起始态=idle 按下点=(2390.4,1247.4)
[drift] 按下后状态=DRAGGING 命中测试=true
[drift] step 1 光标=(2404.1,1254.7) 脸心=(2404.1,1254.7) 漂移=(+0.00,+0.00)
...
[drift] 最大漂移 = 0.000 px  PASS
```

**残留（素材自带，代码无法消除）**：拖拽动画里角色**被拎起来后像钟摆一样摆**——
脸心横摆 45.5 画布 px、整体内容横摆 91.5 画布 px（`tools/measure_frame_drift.py` 实测）。
这是源动画的设计（手是锚点、身体摆动）。想做「锚点锁定」需要逐帧脸心轨迹，
但拖拽态的肤色块检测只在 17/62 帧上成立（头被头发遮/歪），轨迹不可靠，
**未做**（宁可留素材自带的摆动，也不要一个抖动的假锚点）。

### 4.4 自检模式（`--shot=<目录>`）

逐态切过去 → 快照 PNG + **几何断言**：视图在场景里的实际位置/尺寸必须等于
`cellX×scale, cellY×scale, fw×scale, fh×scale`，且必须完整落在舞台内。

这条断言就是 v1 那个 bug 的回归守卫 —— v1 跑这个自检会直接 GEOM-FAIL。

## 五、DSH 宿主接入（真实工作状态）

### 5.1 契约

参考实现 `PC2005-cloud/dsh-pet`（MIT）的宿主 HTTP 契约：

| 项 | 值 |
|---|---|
| 基址 | `http://127.0.0.1:<port>/dsh-pet-7340` |
| 读状态 | `GET /state?since=<counter>&timeout=<ms>`（成对必填，≤10000ms；counter 变了立刻返回） |
| 工作状态 | `sections.workStatus.data = {state, task}`，`state ∈ thinking\|working\|result\|waiting\|success\|error\|null` |
| 占用锁 | `pets.<id>.lock.data = {locked, expiresAt}`（`expiresAt` 是唯一真相，宿主不推「锁没了」） |
| 位置指令 | `pets.<id>.position.data = {x, y, mode, duration?}`，x/y 是**宠物中心**的归一化坐标 |
| 上报实况 | `POST /pose/report?pet=<id>`，体 `{x, y, facing}`（宿主只存内存快照，不写 /state） |
| 端口 | 独立模式默认 3080（被占则顺延，扫 25 个）；运行状态写在 `~/.dsh-pet/standalone-runtime.json`。**DSH 宿主模式的路由挂在 DSH 自己的 web 服务上，端口不在自动发现范围，要用 `--dsh-port=` 指定** |

### 5.2 优先级：用 dsh 那一套

dsh 的档位序（`host/src/host/work-status.ts` 的 `WORK_STATUS_PRIORITY`，逐字对齐）：

```
waiting 60  >  error 50  >  working 40  >  thinking 30  >  result 25  >  success 20
```

**这张表是宿主合并多会话时用的**（`pickDisplayed`：所有会话里取优先级最高的那条，同级取最近更新的）。
我们从 `/state` 读到的 `sections.workStatus` 已经是合并后的唯一档位 —— 优先级在宿主侧生效过一次。

所以本项目的判定是：

- **DSH 事件抢占本地态**（随机链 / 菜单点播）时**直接抢占**，不套 `states.json` 的 priority 表。
  这正是「用 dsh 的优先级」的落点：states.json 那张表把 `waiting`(1) 排在 `calling_tool`(2) 之后，
  用它判的话「等待批准」就盖不住「正在干活」。
- **DSH 事件之间**：跟随宿主，不在客户端再比一次 rank。
  原因：同一会话的正常递进是**档位序下降**的 ——
  等待批准 `waiting`(60) → 用户批准 → 开始干活 `working`(40)；
  工具调用 `working`(40) → 工具返回 `result`(25)。
  客户端按序再拦一次，宠物会永远卡在「等待」上。
- **终态**（`success` / `error`）永远接管，且是**播一遍**的一次性演出。

### 5.3 档位 → 八态映射

| dsh 档位 | 档位序 | 本项目状态 | 播放语义 |
|---|---|---|---|
| `thinking` | 30 | `thinking`（托腮思考） | 循环播 |
| `working` | 40 | `calling_tool`（调用工具） | 循环播 |
| `waiting` | 60 | `waiting`（等待） | 循环播 |
| `result` | 25 | `thinking`（整理 = 消化结果） | 循环播 |
| `success` | 20 | `complete`（完成） | **播一遍** → 回落待机 |
| `error` | 50 | `error`（出错） | **播一遍** → 回落待机 |
| `null` | — | 回落待机 | 当前段**播完即停**，不硬切 |

### 5.4 三条护栏（对齐 dsh-pet 的 handleEnded / resumeWorkStatusAnim）

1. **用户交互优先**：拖拽期间宿主改档位 → **整拍丢弃**（存 `pendingTier`），
   松手时恢复到当前档位（非终态）或回落待机（终态/无档位）。
2. **占用锁冻结**：锁生效时冻结自播与**自动来源**的档位事件；
   动画**播到最后一帧就停住**（`AtlasPlayer.setFrozen`），动画链不推进。
   `expiresAt` 到点由渲染端自己定时解除（宿主不推）。解锁后重新对齐当前档位。
3. **终态一次性**：终态播一遍回落待机，随后随机链恢复（对齐 dsh-pet 的终态气泡语义）。

## 六、DSH 档位宿主：插件形态（dsh-pet-status）

### 6.1 为什么要有它

DSH 宿主里的 dsh-pet 插件（`dsh-pet/src/host/work-status.ts`）用 `ctx.on('session/event', …)`
在**宿主进程内**监听会话事件，聚合成 `workStatus` 写进 `/state`。本机：

- `~/.dsh/plugins` **不存在** → dsh-pet 插件没装；
- DSH 自己的 web 服务在 **60060**，但它有**浏览器访问闸门**
  （`decideDesktopBrowserAccess`）：关闭时对**任何**路径都回 `403 Browser access is disabled`
  （连不存在的路径也 403）—— 跨进程客户端读不到；
- 装官方插件要**重开 DSH**（会打断正在跑的任务），而且插件装好后它自己的 Electron 桌宠会一起冒出来。

于是自己写了一个**只做这件事**的 DSH 插件：`tools/dsh-plugin/`（`dsh-pet-status`）。

### 6.2 插件形态

Cordis 插件：`package.json`（`type: module` + `main: index.js` + `dsh.bundle.patch`）
+ `cordis.patch.yml`（挂载声明）+ `index.js`（`export function apply(ctx)`）。

```
DSH 宿主进程
  ctx.on('session/event', …)        ← 实时事件（turn/start / tool/call / tool/result / approval/asked / turn/end / todo/write）
        ↓ 聚合（reduceWorkStatus + pickDisplayed，同一张 dsh 档位序）
  工作状态档位
        ↓ 自起 HTTP（127.0.0.1:3080，被占顺延；**不受 60060 的浏览器闸门影响**）
  GET /dsh-pet-7340/state?since=&timeout=   长轮询
  POST /dsh-pet-7340/pose/report             收桌宠上报的实况
  POST /dsh-pet-7340/work-status              外部槽写入档位（与 DSH 会话一起按序合并）
```

**为什么自起端口而不挂 DSH 的 webServer**：60060 的浏览器访问闸门会挡掉跨进程客户端
（403 "Browser access is disabled"）。自起 3080 也正好是 dsh-pet 独立模式的默认端口，
落在桌宠 `--dsh` 的自动发现扫描范围（3080~3104）内 —— **桌宠 Java 侧一行都不用改**。

### 6.3 在 DSH 里直接安装（应用内 UI）

DSH 桌面版自带插件管理器，侧边栏「插件」页 →「添加插件」→ 在「包名或地址」输入框里填：

| 填什么 | 形态 | 落库结果 |
| --- | --- | --- |
| `desktop-pet/tools/dsh-plugin` | 本地目录（绝对路径） | `link:` 依赖（Windows 上是 **Junction**），改源码即时生效 |
| `D:\...\dsh-pet-status-1.0.0.tgz` | 压缩包 | `file:` 依赖（拷贝），改源码要重装 |
| `dsh-pet-status` | npm 包名 | 需先发布到 npm（包名要全局唯一） |

UI 的输入框文案就是「输入插件的包名、GitHub 仓库地址或本地目录路径」，
**本地目录路径是一等公民**（`parseInstallSpec` 里 `path` / `tarball` / `git` / `registry` 四种形态）。

命令行等价写法（与 UI 走同一套逻辑）：

```powershell
$env:ELECTRON_RUN_AS_NODE='1'; $env:DSH_HOME="$env:USERPROFILE\.dsh"
& "...\DSH NEXT.exe" --expose-internals "...\resources\app.asar\lib\plugin-cli.js" `
  desktop add desktop-pet/tools/dsh-plugin
```

也可以直接双击插件目录里的 `install.bat`。

安装链路（UI 与 CLI 共用 `runProfilePnpm`）：

1. **装前版本闸门**：读 spec 指向的 `package.json`，用 `engines.dsh` 对照运行时版本
   （`@deepseek-ai/dsh-app-boot` 的版本，本机 `0.2.1-rc.2`）。不满足就在 pnpm 跑之前
   报 `incompatible-version`，不下载任何东西。
2. `pnpm add <spec>`（裸 Windows 绝对路径会被 pnpm 记成 `link:`，**全程离线**，约 0.4s）。
3. `reconcile()`：把声明了 `dsh.bundle` 的新包加进 profile 的 `dsh.profile.bundles`，
   并把它的 bundle patch 叠进配置树。
4. 装后复检已装包的兼容性；不兼容则回滚清单与锁文件并重装旧版本。

**不用重开 DSH**：桌面 profile 支持热加载，装完立即生效（实测卸载后 3080 监听消失、
重装后 1 秒内重新监听）。

> 注意：`link:` 与 `file:` 的区别只在「改源码要不要重装」。开发用 `link:`（Junction）。

### 6.4 包结构规范（能被 DSH 认成 bundle 的硬性字段）

| 字段 | 要求 | 不满足的后果 |
| --- | --- | --- |
| `dsh.bundle.patch` | 指向 `cordis.patch.yml` | 不算 bundle，只当普通依赖，`dsh.profile.bundles` 里挂不上 |
| `cordis.patch.yml` | `- insert: [{id, name}]`，`id` 与包名一致，**该行不能有行尾注释** | 商城预检抓不到 entry ID → `SUBMISSION_ENTRY_MISSING` |
| `icon` | 相对 `package.json` 的路径；`.svg/.png/.jpg/.jpeg/.webp`；≤256 KiB；realpath 后必须留在包目录内 | 插件页无图标（读取方是 app-boot 的 `iconOf`，会内联成 base64） |
| `exports["./package.json"]` | 必须显式导出 | app-boot 的 `readPluginMeta` 读不到 manifest → **图标与标题一起没了** |
| `locale/en.json` + `locale/zh.json` | `{"meta":{"title":"…","description":"…"}}` | 插件页显示英文包名 + 一串 description |
| `engines.dsh` | 半版本范围，如 `>=0.2.1-rc.2` | 不写则改用 `peerDependencies` 判定；写错则安装被拒 |
| `dsh.compatibility.dshReleases` | 逐版本声明 `compatible/incompatible/unknown` | 上架市场时的兼容证据（安装路径不读它） |

`exports` 漏了 `./package.json` 是最容易踩的坑：**图标与标题一起静默消失**，插件页只剩一行裸包名。

### 6.8 进程托管：插件兼当桌宠的进程宿主

插件原本只「报档位」，桌宠本体是独立进程、要人手动起。
现在把「起桌宠」也收进插件生命周期：**装上插件 → 桌宠自动出现；卸载插件 → 桌宠自动消失；崩了自动重拉。**

**桌宠 Java 侧一行没改** —— 桌宠是否存活靠 HTTP 契约判断（「`/state` 有没有未决长轮询」），
托管逻辑全在插件里（`tools/dsh-plugin/pet-supervisor.js`）。

#### 三个必须处理干净的问题

| 问题 | 朴素做法为什么不行 | 本项目的做法 |
| --- | --- | --- |
| **不能双开** | 用户可能已经手动起过桌宠，插件再拉一个就变成两只 | 判据是**活连接**（`/state` 未决长轮询数 > 0），不是时间戳 |
| **不能留孤儿** | 插件卸载 / DSH 关闭时，它拉起的桌宠得跟着走 | 归属记在 `~/.dsh-pet/pet.lock.json`（pid + owner），换手时改写 owner |
| **崩了要能回来** | 桌宠异常退出就没了 | `autoRestart` + 退避重拉 |

> **时间戳 vs 活连接**：判据如果用「最近一次取档位的时间」，
> 就分不清「18 秒前还活着」和「18 秒前就已经死了」—— 宽限期一过就会误拉一只。
> 所以判据必须是「此刻还有没有未决的长轮询请求」。

#### 三种模式

| 模式 | 触发条件 | 对桌宠生死的态度 |
| --- | --- | --- |
| `adopted` | 锁文件里的 pid 还活着（典型：插件热重载后旧进程遗留） | **接管**：改写 owner，不重复拉 |
| `external` | 宽限期 5s 内发现有活连接 | **不碰**：不接管生死，只用看门狗盯着 |
| `spawned` | 宽限期 5s 内没有任何活连接 | **自己拉起**，并负责收尾 |

`external` 模式下有个看门狗：连续 30s 没有活连接 → 判定那个桌宠已退出 → 转成 `spawned` 接手拉起。
桌宠是 8s 轮询一次，30s 足够宽松，不会误判。

#### 归属与换手

`~/.dsh-pet/pet.lock.json`：

```json
{ "pid": 17712, "owner": "dsh-pet-status:23328:1792721275653", "startedAt": 1792721275653 }
```

`owner` 是插件实例的身份（宿主 pid + 启动时刻）。插件热重载时新实例会改写 `owner`；
旧实例 `dispose()` 时发现 `owner` 已不属于自己 → **不杀**桌宠。
否则每次热重载都会把桌宠误杀，用户看到的是「插件一重载桌宠就闪一下」。

#### 配置

启动配置按优先级取第一个有效的：

1. `cordis.patch.yml` 里的 `config.launch`
2. 插件目录下的 `pet-launch.json`（本地文件，最常用；**不入库**）
3. 环境变量 `DSH_PET_LAUNCH`（JSON）

| 环境变量 | 作用 |
| --- | --- |
| `DSH_PET_LAUNCH_FILE` | 改用别的路径读启动配置（自测隔离用） |
| `DSH_PET_STATUS_DISABLE_SUPERVISOR=1` | 整体关闭托管，只保留「报档位」 |

`command` 是**数组**（每个元素一个参数），子进程直接按数组 spawn，**不走 shell**。
Windows 上 classpath / module-path 里的分号是字面量。

#### 踩过的坑

| 坑 | 症状 | 根因 | 修法 |
| --- | --- | --- | --- |
| **热重载双开桌宠** | 插件一重载就变成两只 | 「最近见过桌宠」的记忆放在模块级变量里，热重载重新求值模块 → 记忆归零 | 改成落盘 `~/.dsh-pet/pet-seen.json`；最终干脆改用**活连接**判据，从根上不需要这个记忆 |
| **配置带 BOM → 整个托管静默失效** | 插件装着但桌宠不起来，日志里什么都没有 | Windows 上 PowerShell `Set-Content -Encoding UTF8` 会写 BOM，`JSON.parse` 直接抛 | 解析时 `replace(/^\uFEFF/, '')`；顺带**配置解析失败要打日志**，不能静默 |

& "C:\Users\KSO\AppData\Local\Programs\DSH NEXT\DSH NEXT.exe" --expose-internals `
  "C:\Users\KSO\AppData\Local\Programs\DSH NEXT\resources\app.asar\lib\plugin-cli.js" `
  desktop add desktop-pet/tools/dsh-plugin

# 常用参数
#   --height=<px>     角色在屏幕上的高度（逻辑像素），默认按屏高自适应
#   --scale=<倍率>    直接指定缩放倍率
#   --dsh             接入 DSH 宿主（自动发现端口：独立模式运行状态文件 → 3080~3104 扫描）
#   --dsh-port=<端口> 指定宿主端口（DSH 宿主模式必须用它）
#   --dsh-pet=<id>    宠物 id，默认 main

> **参数一律用 `getParameters().getRaw()` 解析**：JavaFX 会把 `--key=value`
> 当成命名参数，`getUnnamed()` 里看不到，直接用 `getUnnamed()` 会导致所有
> `--key=value` 形式的参数静默失效。
